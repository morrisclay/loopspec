## 0. URGENT — the held-out set is about to be destroyed

`benchmarks/held_out/` contains `llm_agent_system`. If URAS pivots to agent loop engineering,
**that becomes the native domain**, and encoding it — or building against it, or reading it

**Do this before any pivot work:** remove `llm_agent_system` from the sealed set and reseal

the substitution and the reason. This is the one irreversible mistake available right now and

## 1. The proposed pivot, and the framing that decides whether it works

**Proposal:** reposition URAS as a cybernetic representation language for agent loop
engineering rather than a universal representation across hospitals, governments and
ecosystems.

**Assessment: methodologically orthodox.** `benchmarks/reference_set.md` already contains the
argument — *"A GAP IN THE CORPUS PRODUCED A WRONG FINDING ABOUT THE ONTOLOGY … derivation from
data is only as good as the data selected."* The present corpus is prose about hospitals and
immune systems with no ground truth and no way to check an encoding against what the system
did. Agent loops supply unlimited real instances, complete traces, and outcomes that arrive.

**Weak framing to avoid:** *universal was too ambitious, so we scoped down.* That is a retreat
and will read as one.

**Strong framing:** *agent loops are the first domain in which cybernetic claims can actually
be checked, so that is where the representation gets built and validated. Universality stops
being a premise and becomes a hypothesis to test afterwards.*

What the pivot fixes that effort has not:

- **The prior-art gate changes opponent.** A universal representation must beat Dec-POMDPs on
  expressivity. A representation language for agent loops must beat *TypeScript plus a prose
  prompt* — which has no goal representation, no uncertainty, no calibration and no authority
  model. Not a lower bar dishonestly chosen; the actual competition in the actual domain.
- **`D` becomes measurable** — see §4.
- **Execution stops being Phase 7.** The compile target exists and is in use.
- **The `hospital and venture, same ontology` overclaim goes.**

### The discriminating test — run it rather than argue it

> **Build against agent loops. Then encode a hospital.**

If it still encodes, universality survives as a **finding** — derived where it could be
checked, transported where it could not — which is far stronger than the original assumption.
If it does not, the institutional primitives were load-bearing and agent loops were too easy a
corpus. Both outcomes are worth having; neither is obtainable without the pivot.

## 2. Correction — most institutional primitives DO transfer

An earlier draft of the pivot note claimed agent loops have no politics and that the
institutional primitives therefore needed protecting from budget pressure. **That was wrong,
and it undersold the pivot.**

| Primitive | In an agent loop | Verdict |
|---|---|---|
| `authority` | What may this agent do without approval? Irreversibly? The central deployment question in agent engineering, and no framework represents it | **Core — plausibly the highest-value primitive for this user** |
| `Consequence` | Asymmetric error cost; asymmetric exposure between operator and agent — the human is fired, the agent is not. Explains overrides that look irrational against the agent's objective | **Core** |
| `Party` | Planner and worker holding different beliefs; human and agent estimating the same quantity. The cause of inconsistent multi-agent output | **Core** |
| `Constraint` | What it must never do regardless of how the reward reads — the guardrail problem stated structurally rather than as imperative code | **Core** |
| `informal_influence` | **Reframe worth testing:** not the water cooler, but belief formed through channels outside the declared evidence path — injected content, retrieved documents, history carried forward. Gives a way to state *"this estimate was shaped by something outside its evidence chain"*, which nothing in the stack can currently express, and names a live security problem | **Retain and re-derive. The reframe is a genuine candidate finding** |
| legitimacy (political) | No analogue — who is permitted to set the goal at all is not an agent-loop question | Institution-only |
| standing | No analogue | Institution-only |

**Therefore: do not protect these as institutional heritage — re-derive them from the agent
corpus on its own terms**, under the normal three-benchmarks rule. If `authority` is demanded
by agent deployment, it earns its place without special pleading.

Protection is needed only for the genuinely unexercised residue — legitimacy and standing.
Suggested rule, narrower than first proposed:

> A primitive may not be deleted solely because agent loops do not exercise it. Deletion
> requires a positive argument that adaptive systems do not need it. Under-exercised
> primitives are marked `institution-only` and the count is tracked as a project metric.

**Commercial consequence worth noting:** calibration and uncertainty are the intellectually
interesting part and the harder sell. *What is this thing allowed to do, and who is
accountable when it is wrong* is what gets paid for. The institutional primitives are where
that lives.

## 3. Guard against the back-door failure

Agent frameworks churn. The charter's standing directive — *prefer concepts that survive the
replacement of today's LLMs* — becomes **harder** to honour when the validation domain is a
2026 practice, not easier.

`Estimator`, `Explanation`, `Calibration`, `Delay` survive an architecture change. `Subagent`,
`Skill`-as-markdown, MCP, context windows and tool schemas do not. The two-column firewall in
`flue_notes.md` was written for Phase 7 and now applies to the whole project: nothing flows
right to left.

The specific failure to watch: optimising against agent loops until the ontology reduces to a
POMDP with better agent ergonomics — which is exactly what the Phase 1 gate exists to catch,
arriving through the back door because the corpus changed rather than because anyone argued
for it.

## 4. The LLM encoder is the missing instrument for `D`

`score.md` calls inter-encoder agreement the most important term and *"the only proposed
measure that tests whether the representation means anything."* It currently has no practical
instrument: two humans give n=2, slowly.

**An encoder given the catalog as context gives n=20 in an afternoon**, and `score.md` already
specifies the comparison — Jaccard on primitive types, fuzzy Jaccard on estimands, agreement
on loop count and topology.

**Build a thin encoder during the 2–4 loop, not after.** The charter prohibits building
*execution* before the primitives settle; an encoder is instrumentation for the convergence
test itself. In the book's vocabulary it is a structural intervention lowering the cost of the
evidence this project most needs.

Three guards, each with a specific reason:

1. **Cross-provider only.** t-minus P5, measured: cross-provider beats same-model reruns
   because independent blind spots. Two runs of one model share a prior and agree for reasons
   unrelated to ontology determinacy. A same-model figure may be reported but must never enter
   the score.
2. **The capability sweep, and this is the important one.** A strong model given a *suggestive*
   catalog still produces plausible, mutually consistent encodings, because its competence
   supplies the determinacy the ontology lacks. High `D` from a frontier model is therefore
   ambiguous evidence, in the flattering direction.
   → **Sweep model capability and measure the slope of `D`.** A determinate ontology is
   encodable by a weak model. A suggestive one needs a strong one. **The slope is a better
   determinacy measure than the value.** Flat is the result to want. Run this before quoting
   any `D` figure as evidence of convergence.
3. **The encoder's system prompt is generated from `primitives.yaml` and may contain no
   disambiguation absent from the catalog.** Otherwise the prompt silently becomes the
   specification and `D` rises while the ontology stays vague. Same shape as *"no term may be
   edited in the same commit as the ontology it scores."*

**And the direction that pays:** not *human writes intent → encoder emits DSL*, but *encoder
reads existing material and proposes the encoding, human corrects it.* **Every correction is a
labelled instance of a primitive boundary being ambiguous** — a map of the catalog's soft
spots, generated by use, at no extra cost. That is a feedback loop on the ontology, which the
project wants and currently lacks a mechanism for.

## 5. Phase 6 design constraint falling out of Phase 5

Because the IR carries invariants, a generated diagram can **draw what is broken** — a
dangling estimand is a node with nothing running into it; an estimator depending on its own
output without a `Delay` is a visible tight cycle; an unclosed loop is an arrow ending in
space. That turns the diagram into a diagnostic surface rather than documentation.

**Consequent constraint: every validator invariant needs a visual failure mode.** If it cannot
be drawn wrong, it probably should not be an invariant. Worth adopting now, as it disciplines
both phases.

## 6. Coupling to the book — what it obliges

The book publishes **only if URAS converges**. Kill criteria here are kill criteria there.
That was chosen deliberately so publication cannot remove this project's freedom to fail.

Two obligations on this side:

1. **The convergence declaration must be written as though the book did not exist.** No book
   milestone, deadline or draft may be cited in the commit that declares convergence. If the
   two are ever argued together in one place, the declaration is void. Schedule pressure will
   push toward declaring early; this rule is cheap now and expensive later.
2. **The book's notation must be generated from `primitives.yaml`, not hand-written**, with a
   mechanical check that fails when the book references a primitive the catalog no longer
   contains. This is not hypothetical: the book's `NOTATION.md` went stale within hours when
   `Explanation`, `determination` and `Calibration.window` landed. A small tool in `tools/`
   would prevent it recurring.

**What the coupling buys this project:** a real test of the success criterion *"experts from
multiple domains recognize their systems"*, which currently has no instrument. Founders reading
an encoding of their own company back is a usability trial against a non-expert population and
a better probe for the comprehensibility term than anything in `tools/score.py`.

## 7. Candidate finding — uncertainty on `DesiredCondition`

From the book's notation work:

```yaml
confidence_in_target: 0.7
```

Not expressible in the current catalog. Uncertainty attaches to `Estimate`; there is no
representation for *how confident the holder is that this is the right desired condition* —
uncertainty about what one wants rather than about the world.

Arguments it is real: it is the natural companion to `Revision`, since a condition held at 0.7
and one held at 0.99 warrant different revision policies and the catalog cannot say so;
Hop Aero and Lodestar both hold targets set outside their boundary, which is exactly where
confidence in the target is low; and it may explain refuted-versus-abandoned from the other
end, since a goal abandoned rather than refuted may be one never firmly held.

Arguments it reduces: it may be an `Estimate` over a meta-estimand and need only a convention;
or it may belong to `PreferenceOrdering` as ordinal instability.

**One book sketch is not three benchmarks across two domains. It does not enter the catalog on
this evidence.** Test against `democracy` and `military_command`, both of which should stress
goal provenance.

## 8. Flue — two open questions answered, one that now matters more

Verified against `@flue/runtime` 1.0.0-beta.9 in a running deployment rather than the
marketing page:

- `defineAgent(() => ({ model, instructions, actions }))`; workflows default-export
  `run(ctx: FlueContext)`.
- **The termination mismatch is confirmed in shipped code, not inferred.** A production comment
  describes a workflow as *"a bounded, result-returning operation … it terminates and yields an
  IC brief; durable state lives in the graph."* Flue workflows terminate; URAS loops do not.
  The Durable Object route remains the resolution.

Still open, and one is now on the critical path: **can evidence chains be reconstructed from
durable stream records, or only replayed?** Calibration requires an immutable record of what
was believed *before* an outcome arrived. If records are replay-only, calibration cannot be
built on them and that is a Phase 7 finding with consequences for the representation.

Also still open: whether subagent nesting is true recursion — the book's chapter on nested
loops needs an answer, and so does recursive viability.
