# Real-loop tranche 1 — results

Date: **2026-08-04**  
Scope frozen before linting: Ralph, karpathy/autoresearch, SWE-agent DefaultAgent, and
Browser Use Agent, on top of the repository's existing published-example and field suites.

## Outcome

The corpus gate now validates **21 unique encodings**. Three new runtime cases are pinned to
full upstream commit hashes, and 16 named candidates are queued across coding, research,
browser, framework, and evaluation strata.

The three new encodings initially produced 27 findings. Correcting source-inconsistent
encoding choices reduced that to **12** without changing the source systems or weakening the
gate. That reduction is evidence of encoder sensitivity, not evidence that the systems
became better.

| case | final findings | strongest source-backed reading |
|---|---:|---|
| autoresearch | 2 | each hypothesis settles against validation BPB, but there is no declared cross-run calibration of the agent's hypothesis-selection judgement |
| SWE-agent | 6 | submission is endogenous; the external acceptance result is not joined back into the inner loop, and the default loop has no escalation point |
| Browser Use | 4 | action outcomes settle local action bets, while completion remains a model judgement; concrete browser actions have deployment-specific reversibility and authority |

## Adjudication by root cause

### Source-backed system properties

- **Autoresearch separates settlement from calibration.** Every candidate is evaluated and
  kept or discarded by a fixed metric. The result ledger is feedback. What is absent is a
  declared review that scores the agent's past *candidate-merit judgements* over a window and
  changes its method or trust.
- **SWE-agent's inner loop ends at submission, not acceptance.** Its own patch is the terminal
  signal. The later benchmark grader is outside the encoded run, so
  `endogenous_feedback_without_crosscheck`, `process_path_not_declared`, and
  `belief_never_checked` are three views of one root issue rather than three independent
  defects.
- **SWE-agent autosubmits after bounded internal errors.** That is a real stop behavior, and
  no human escalation is declared inside the default agent loop.
- **Browser Use has genuine balancing mechanisms.** It counts consecutive failures, detects
  repeated actions and stagnant pages, injects replanning nudges, enforces step and failure
  ceilings, and permits external pause/stop. A loop analysis that calls it simply
  "unbounded" would be wrong.
- **Browser Use's default post-run judge is still endogenous.** It is a second model
  judgement over the trace, not a user-confirmed outcome or a calibration program for the
  completion judge.

### Encoding corrections

The first pass modelled bookkeeping and controller operations as if they directly changed
world quantities. That caused spurious process-path, model, direction, and reversibility
findings. The corrected encodings distinguish:

- world actions that can change the controlled process;
- controller updates such as replanning;
- terminal operations such as submit or declare-done;
- observations that actually return to a decision rule.

This distinction should become explicit in the authoring language; today it depends on
encoder discipline.

### Language or check gaps

1. **Settlement and calibration were conflated in the headline copy.** The check now says
   when individual calls settle but aggregate calibration is absent. A regression test holds
   that distinction.
2. **Authority is narrower than real operator control.** LoopSpec represents per-action
   approval, but not who may start, pause, resume, interrupt, or terminate the whole loop.
   Consequently `consequence_without_authority` overstates cases where a human can stop the
   system but does not approve every act.
3. **Generic actions are parameterized.** A browser or shell action has no single truthful
   reversibility value until a concrete tool and deployment are bound. The language needs a
   way to mark a property as deployment-bound without treating omission as a completed
   design.
4. **Terminal outputs are not feedback observations.** Patch submission and `done` are
   outputs or claims. Encoding them as observations makes checks think they are part of a
   closed feedback path. A small `outputs`/`claims` construct may be warranted, but only
   after independent encodings reproduce the problem.
5. **Finding count exaggerates insight count.** Three SWE-agent checks describe the same
   missing acceptance join. Default CLI output should group by causal root and consequence,
   not present each structural projection as a separate problem.

## Keep, change, defer

**Keep**

- source-pinned cases and a mechanical corpus gate;
- `settled_by` as distinct from calibration;
- explicit unknown reversibility as a useful incomplete-design signal;
- the separation between framework runtime and instantiated application.

**Changed now**

- added the real-loop registry, validator, and three source-pinned encodings;
- corrected the `belief_never_checked` message so it no longer denies real per-case outcome
  feedback;
- removed the obsolete claim that no framework represents approval gates;
- added a regression test for settlement-versus-calibration wording.

**Defer until held-out encoding**

- a loop-level authority block (`may_start`, `may_pause`, `may_stop`);
- a deployment-bound or parameterized action profile;
- terminal `outputs` or `claims` separate from feedback observations;
- root-cause clustering in the CLI.
